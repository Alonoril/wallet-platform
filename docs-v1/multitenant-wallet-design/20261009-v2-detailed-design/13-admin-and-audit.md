# M13：管理控制台、变更审批、熔断与审计

返回 [设计总览](README.md)。关联需求：提现风控、密钥生命周期、租户配置、异常资金处理与操作追溯。

> 工程位置：`wallet-core::admin` 负责管理业务，`wallet-app::admin_http` 提供同进程管理入口。

## 1. 职责与身份边界

本模块提供平台管理命令、审批事实和审计证据，不直接执行余额 SQL 或原始签名。租户自助管理与平台运营后台分开授权，使用不同管理主体、会话、scope 和 listener/路由授权，仍在同一应用。

本版使用项目内管理账号、Argon2id 密码哈希、MFA 和短时会话，不依赖第三方身份平台。TOTP 按 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html) 实现，密钥由通信 Vault 封装；窗口、重复计数与登录限流受控，恢复码高熵、仅哈希存储且单次使用。敏感操作二次认证并检查最新权限；MFA 重置本身走高风险审批。浏览器不持有资金解锁秘密、链私钥或任意签名权限。

解锁是 M03 的本地仪式；管理 HTTP 只能批准其范围/变更、查询状态和请求锁定，不能提交助记词或解锁秘密。首管理员初始化使用受控本地维护模式，不公开匿名注册。

## 2. 角色矩阵

| 角色 | 能力 | 限制 |
|---|---|---|
| 租户管理员 | 管理本租户接入公钥、Webhook、允许的业务冻结 | 不能解平台风险 Hold、改签名限额或跨租户访问 |
| 平台运营 | 查询订单、调查入款、发起配置/补仓申请 | 不能自己批准高风险申请 |
| 风险审核 | 审批提现/地址政策、创建/释放风险限制 | 不读取私钥或直接签名 |
| 资金管理员 | 提议金库/冷热调拨、费用资本补充 | 不绕过 M03 用途白名单与硬额度 |
| 安全管理员 | 密钥仪式、本地解锁范围、紧急暂停 | 恢复/轮换需要独立复核；不任意改用户余额 |
| 审计只读 | 查看凭证、链事实、审批与变化证据 | 不执行资金操作 |

权限绑定租户/链/资产作用域和动作，不用“超级管理员”作为常规运行身份。基础设施紧急权限单独记录、限时启用并事后审计。

## 3. 管理视图

| 页面 | 必须展示的业务信息 |
|---|---|
| 租户/用户 | 状态、启用网络/资产、限制与策略版本 |
| 余额/冻结 | 可用、提现/业务/风险 Hold、具体发行者与剩余额 |
| 充值 | 归属、确认策略、最终性、异常原因与凭证 |
| 提现审核 | 用户、精确资产/金额/服务费/目的地址、风险证据、批准有效期 |
| 归集/Gas | 未归集敞口、实际成本、补 Gas 状态、例外队列 |
| 金库/热钱包 | 角色、资产、物理预留、运营资本与暴露上限 |
| 对账/工单 | 同检查点差异、影响范围、拟修复凭证与审批 |
| 密钥生命周期 | 用途、版本、状态、恢复验证结果；不显示明文种子/xpub |
| 回调/任务 | 投递结果、死信及可重放范围 |

所有页面查询都带授权作用域与 cursor 分页；导出操作有字段白名单、授权、审计和有效期，不导出敏感凭据。

## 4. 变更数据模型

| 表 | 字段与约束 |
|---|---|
| `admin_principals` | `id, login_name, password_hash, mfa_key_ref, roles, scopes, state, version` |
| `change_requests` | `id, kind, scope, immutable_payload, payload_hash, expected_versions, requester, expires_at, state` |
| `change_approvals` | `change_id, approver, decision, payload_hash, auth_strength, approved_at`；批准身份唯一 |
| `admin_command_executions` | `change_id, module, command_id, result_ref, state`；模块命令幂等 |
| `pause_controls` | `id, scope, epoch, reason, issuer, state, expected_version` |
| `audit_events` | `event_id, actor, scope, action, resource, before_hash, after_hash, request_id, change_id, result, audit_seq` |

审批对象不可变；修改内容必须生成新申请。执行前检查批准者仍有效、申请未过期、payload hash/资源版本一致，不能复用另一变更的批准记录。

## 5. 高风险动作审批

| 动作 | 必须满足 |
|---|---|
| 大额提现、金库/冷钱包调拨 | 金额/目的地绑定，不同操作人员批准，M03 精确许可 |
| 新金库/提现白名单目的地址 | 验证所属钱包/密钥公钥关系、冷静期与双人复核 |
| 根密钥生成、恢复、轮换 | 建钥仪式/恢复证据，安全与资金角色协同 |
| 风险 Hold 释放/损失纠正 | 发行者授权、工单、具体分录与影响确认 |
| 新链/新代币、精度/行为 Profile 变更 | RPC/行为/最终性验收，版本化生效高度 |
| 提高钱包额度/费用预算、降低最终性 | 独立评审批准，不被普通配置编辑直接应用 |
| 受控重放/Nonce 取消 | 关联原业务事实，禁止借此新建重复付款 |

普通紧急暂停可以由指定安全/风险人员立即执行，恢复要求双人复核与 M12 检查点。申请人/批准人分离，两个批准不能来自同一身份。批准策略本身的降低也必须走高风险审批。

## 6. 同进程熔断与准入竞态

scope 为全平台、租户、链、资产、钱包或 key version；动作可分别控制资金受理、签名准入和普通广播。作用域控制行在资源创建时建立，控制/签名事务以相同稳定顺序锁定，避免缺失控制行或缓存漏检。

```text
暂停：先关闭对应运行时准入 gate。
→ 单 PG 短事务锁控制行，提升 epoch，写 PAUSED + 审计事实 + Outbox。
→ 提交后通知本进程任务；每次签名准入仍从 PG 检查最新 epoch。
→ 提交失败保持本地 gate 关闭和 PAUSE_PENDING，告警并补持久化。

恢复：保持 gate 关闭，完成对账/风险检查与双人批准。
→ 单事务条件核对 epoch/配置版本，提交 ACTIVE + 新 epoch + 审计。
→ 持久证据与运行会话均就绪后开放 gate；失败仍拒绝新准入。
```

M03 `SIGNING` 准入与暂停锁相同控制行。暂停提交前已经准入的操作按可能已签处理，暂停后不再批准普通新操作；不在签名计算期间持有资金长锁。用户可见暂停结果包含 epoch、在途签名/可能付款数量，不能声称所有交易已停止。

同一数据库只有一个权威暂停状态；没有 Core/独立策略库两侧提交协议。运行时 gate 用于快速阻断，持久 epoch 用于重启与最新事实检查，不能只等缓存/Outbox 失效。

已签交易可被网络中副本广播，锁定或暂停不能撤销它。恢复/取消签名需要例外许可并追踪原 Nonce 竞争，不能据暂停自动解冻。数据库/证据整体回退时 pause epoch 也可能回退，只有未回退检查点能够揭示；无证据则进入恢复屏障。

## 7. 审计完整性

资金/配置动作保存申请、批准、执行和结果四类证据，关联 operation、journal、execution、grant 和链 hash。只记录必要的公开地址/业务字段，敏感内容加密保存，日志里没有助记词、DEK、签名私钥。

关键管理授权/许可必须先有同库审计事实，执行与结果按 M03/M11 协议确认本地证据；证据不可用拒绝新增高风险执行。紧急暂停先关闭准入，即使证据暂不可写也不阻止安全动作，保留待补事实并告警。一般运行日志可异步，但资金和安全证据不丢弃。

项目内审计采用同库追加事件和本地文件 hash 链/序号，由独立用途审计 key 签名检查点，周期导出到运营保管的离线介质；不依赖外部审计平台。敏感载荷由证据 Vault 加密，校验文件尾部/水位与备份版本。

同机 hash 链/签名 key 不能抵御主机控制者重写记录或伪造解锁后的检查点；未被一起改写的离线检查点只能验证其覆盖范围，不能证明导出后没有遗漏事件。表权限、追加协议和多人复核为软件/运营控制，不能标成硬件防篡改。

审核数据查询、批量导出、权限赋予及失败的越权尝试也记录。保留期由业务与适用要求配置，不在代码写死。

## 8. 修复与重放入口

后台操作调用模块命令，例如 `ApproveWithdrawal`、`ReleaseRiskHold`、`ExecuteCorrectionPlan`、`RetryWebhookDelivery`、`RequestNonceBarrier`。命令携带 `command_id, change_id, expected_version, actor_context`，重复执行返回同结果。

没有“任意改余额”“任意改状态”“清空 Nonce”“复制订单再支付”按钮。手工链交易先登记意图/精确载荷，再跟踪与入账；人工决定也必须符合资金不变量。

## 9. 管理接口、指标与验收

| 控制面接口 | 输入与结果 |
|---|---|
| `CreateChange` | 管理身份、scope、typed payload、资源版本 → 不可变申请/hash |
| `ApproveChange` | 申请 ID/hash、独立批准者和认证强度 → 追加批准事实 |
| `ExecuteChange` | 申请/command ID、预期版本 → 模块幂等指令与结果引用 |
| `EmergencyPause` | 允许的应急身份、scope、理由 → 单调 epoch、持久暂停状态和在途操作范围 |
| `ResumeScope` | 多人批准、恢复检查点和目标 epoch → 受控恢复结果 |
| `ReadAudit` | 只读身份、授权范围、cursor → 脱敏审计证据 |

管理 HTTP 入口独立于租户开放 API；浏览器会话需 CSRF 防护及敏感动作二次认证。每个 endpoint 都有动作与资源级授权，不仅在前端隐藏按钮。

监控高风险申请/拒绝、批准耗时、运行 gate 与持久 epoch 不一致、审计水位落后、敏感权限变化和异常导出。

- 同一人不能完成双人审批；批准后修改金额/目标/配置版本不能执行。
- 租户管理员无法释放平台 Hold、提高 Vault 签名限额或查询其他租户。
- 紧急暂停立即关闭本地准入，持久化失败保持关闭；并发签名按准入提交点区分在途范围。
- 恢复须有对账证据与批准；可检测回退保持屏障，缺少最新证据时不能断言 pause epoch 从未回退。
- 每个纠错/重放/取消命令都可追踪到申请、批准、模块结果和账本/链证据。
- 明文密钥、全量 xpub 和无限签名能力在后台与导出中均不存在。
