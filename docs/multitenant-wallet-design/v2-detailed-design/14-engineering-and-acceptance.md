# M14：工程边界、实施拆分与验收

返回 [设计总览](README.md)。本模块将 M01–M13 的契约转为一期工程与交付任务。

## 1. 工程组织原则

逻辑模块独立，资金事务保持在可组合的 Wallet Core 内；只有网络、身份、密钥或运行负载边界需要时拆独立进程。不要把文档中的 14 个模块机械变成 14 个微服务。

拟实施结构如下，当前仓库尚未创建这些目录：

```text
crates/
  wallet-types/              # 标识、精确金额、不可变跨模块 DTO
  wallet-domain/             # 纯业务规则、状态与转移 guard
  wallet-core/
    src/tenant/              # M01
    src/api/                 # M02
    src/address/             # M04
    src/deposit/             # M06 充值业务部分
    src/withdrawal/          # M08
    src/risk/                # M08 规则/额度/审批
    src/custody/              # M09/M10 策略与预留
    src/events/              # M11
    src/reconciliation/      # M12
    src/admin/               # M13
  wallet-ledger/             # M05 唯一资金写入口
  wallet-storage/            # SQLx、迁移、UnitOfWork 与受控仓储
  wallet-chain-core/         # 链无关语义与能力契约
  wallet-chain-evm/          # M06 扫描、M07 执行/费用/最终性适配
  wallet-signer-protocol/    # 许可、精确载荷与结果 DTO，无私钥材料
services/
  wallet-api/                # HTTP、控制面、资金受理
  wallet-worker/             # 索引、执行、归集、对账等分角色运行
  webhook-worker/            # 受限公网出站，M11
  wallet-signer/             # M03，隔离构建/部署/持久存储
migrations/
config/examples/            # 只含占位配置，不含凭据
tests/                       # 跨模块、资金与故障恢复场景
docs/multitenant-wallet-design/v2-detailed-design/
```

同一个 worker 可按职责运行多个副本/角色，Indexer 和执行器的 PG 角色及 KMS 权限不混用。Signer 程序不依赖开放 API 或核心领域的可变业务服务，只消费受限协议和独立策略事实。

## 2. 依赖与事务契约

| 层 | 依赖范围 |
|---|---|
| `wallet-types/domain` | 精确整数、标识与纯规则，不调用 PG/RPC/KMS |
| `wallet-ledger` | 受控过账仓储及事务上下文，不主动发链交易 |
| `wallet-core` | 业务模块、账本、仓储和事件接口，不读取私钥 |
| `wallet-chain-core/evm` | 语义意图、RPC、序列化、费用及执行事实 |
| `wallet-signer-protocol` | 公开可验证载荷，不持有 seed/xprv |
| 服务进程 | 组装配置、身份、连接池、任务及观测 |

共享 PG 的资金操作通过同一 UnitOfWork 组合。例如提现受理必须把幂等、订单、Hold、额度和 Outbox 放在一项事务。不能让每个仓储 helper 私自提交，导致表面上调用了一次业务服务但实际上分成五个事务。

锁定约定：先业务聚合/控制行，再按稳定账户 ID 锁账本投影，再按确定键锁额度/钱包预留；Nonce 在独立准备事务按钱包锁。所有会组合的指令复用同一顺序，死锁做有限重试。任何外部 I/O 不持有资金长事务。

## 3. 链无关类型边界

| 类型/接口 | 核心字段与能力 |
|---|---|
| `ChainId/AssetId` | 命名空间与稳定资产身份，不只用 EVM u64 |
| `AssetAmount/LedgerUnits` | 前者受链单笔边界限制，后者支持有界大整数汇总 |
| `ChainAddress` | 适配器规范字节与展示编码，不固定全链 20 字节 |
| `TransferIntent` | 来源策略、目的地址、资产、金额与业务用途，无通用 gas/nonce 字段 |
| `FeePlan` | 各费用资产的预留上界、有效期和适配器数据 |
| `ExecutionSlot` | EVM Nonce、其他链有效期/引用信息等链特定变体 |
| `MovementFact` | 资产移动、来源定位、块身份和解析版本 |
| `FinalityEvidence` | 规范块、最终性策略、需要的外部锚定证据 |
| 适配器能力 | 地址校验、扫链、费用报价、构建、广播、效果检查、最终性 |

一期用明确 EVM 路由，不先写需要 trait object 才能解决的泛化框架。以后增加 TRON/Solana 适配器时复用用户/账本/Hold/审批，重做链密钥派生、费用、交易有效性和执行证明。

## 4. Rust 风格与性能

Rust 2024，缩进使用 tabs，crate 级导入分组并重排模块；实现阶段提交并使用 `rustfmt.toml` 与 `clippy.toml`。手写 `.rs` 不超过 500 行、函数不超过 120 行，使用领域名称，不使用 `foo/bar/tmp/data/obj` 等泛化标识。

热点优先借用、避免无意义 clone/中间集合。API 请求只做必要的有界内容读取与一次规范摘要；raw tx/事件持久字节复用；链 RPC 批处理但限制请求规模、响应内存和并发。确需拥有数据跨越任务边界时明确转移 ownership，`Cow` 用于可借用但有 owned fallback 的边界。

金额转换不得经浮点。PG→Rust 的整数校验、API 字符串规范、链 U256 上界和账本汇总上界共用定义。扫描和历史流水使用 cursor/增量处理，避免全租户数据装入内存。

## 5. 数据库与迁移

迁移分为租户/注册表、账本/Hold、链事实/覆盖、订单/执行、任务/审计、独立 Signer 存储。首先落地唯一性、组合外键、已过账保护与平衡约束，再开放资金接口。

大表索引、分区和历史归档按实测数据量决定。唯一性不能因分区丢失全局业务订单/Nonce 约束；必要时保留未分区的唯一身份目录。归档不删除可影响当前资金、旧地址和可能签名交易的事实。

配置以引用 Secret/Vault 的方式注入；生产/测试完全分离。地址注册、已签交易和账本数据的迁移采用向前兼容策略，旧策略/解析版本仍能读取，不把部署回滚当成资金历史回滚。

## 6. 拟配置的开发命令与环境

Cargo workspace 建立后纳入以下检查；当前文档仓库不能直接运行这些项目命令：

```bash
rtk cargo fmt --all -- --check
rtk cargo clippy --workspace --all-targets -- -D warnings
rtk cargo test --workspace
```

本地集成环境使用隔离 PostgreSQL、可故障注入的 RPC/Signer mock、EVM 本地链及模拟外部租户。助记词/私钥只使用明确的非生产测试向量；生产密钥不可进入本地环境或 CI。真实云 KMS/真实 RPC PoC 使用独立低权限环境，逐项验证能力。

实现前分析影响范围先用 codegraph；没有索引时使用仓库搜索。Rust 符号/类型/编译相关变更先运行 rust-analyzer。本文不包含可编译 Rust 实现，不声称已有代码检查通过。

## 7. 交付阶段

| 阶段 | 模块与成果 | 离开阶段的条件 |
|---|---|---|
| P0 契约与能力验证 | 链/资产清单、费用口径、密钥/审批/恢复方案 | RPC trace、最终性、KMS/派生、资金账本口径确认 |
| P1 核心账户 | M01–M05、M11/M13 基础 | 安全接入、稳定地址、平衡账本、并发 Hold、发行清单 |
| P2 受限执行 | M03/M07 的完整签名与恢复协议 | 可能签名边界、原 raw 重播、替代/取消、独立许可日志 |
| P3 充提闭环 | M06/M08/M10 基础、M12 对账 | 单链/少量白名单资产最终充值与安全提现、Gas 资本覆盖 |
| P4 归集优化 | M09、多资产补 Gas、流动性调度 | 成本基线比较，敞口/时效约束同时满足 |
| P5 灰度交付 | M11–M13 完整、审计与灾备 | 故障矩阵、恢复演练、运营手册、低额度逐步放量 |

时间/人力依团队和目标链实测后估算，不把概念设计中的周数视为承诺。新网络按独立准入清单走完 P0/P3 的链特定验收。

## 8. P0 验收矩阵

| 场景 | 预期结果 | 模块 |
|---|---|---|
| 重放签名、跨租户 UUID、伪造内部头 | 拒绝，零资金副作用 | M01/M02 |
| 同业务同键重试/同键不同金额 | 原订单或冲突，不重复 Hold | M02/M08 |
| 同用户并发开户/地址任务重启 | 稳定映射、唯一索引与地址 | M01/M04 |
| 发行地址与扫描缓存切换并发入款 | 完整回填，仅一次有效入账 | M04/M06 |
| 并发提现、冻结、部分解冻 | 无负可用，Hold 合计正确 | M05/M08 |
| 篡改金额/网络/合约/路径/目标 | 独立 Signer 拒绝 | M03/M07 |
| 普通/内部 native 转入、祖先回滚 | 去重，回滚路径不入账 | M06 |
| ERC-20 同名假币、false 返回、升级 | 不错误入账/结算，必要时隔离 | M04/M06/M07 |
| 补 Gas 到用户地址、归集到金库 | 只迁移托管资产，不增加用户负债 | M05/M06/M09 |
| 扫块分页截断/trace 缺失 | 完整覆盖不推进，不错误确认 | M06 |
| 浅重组、深重组及再次包含 | 审计冲正/例外，无重复净入账 | M06/M12 |
| Signer 请求发出后响应丢失 | Hold 保留，恢复原许可与执行 | M03/M07/M08 |
| 签名已存而广播/业务 DB 未完成 | 同家族恢复，不新 Nonce 付款 | M07 |
| 付款与取消竞争 | 依据唯一最终生效成员结算 | M07/M08 |
| 未知 Nonce/钱包出向 | 暂停、对账，不跳过后续重付 | M07/M12 |
| 同钱包多调度器、旧余额快照 | 付款/Gas 不超额，实际效果只扣一次 | M10 |
| Gas 暴涨、补充不确定、多 token 部分失败 | 有预算的恢复，无无限补币 | M09 |
| 原生资本不足而 token 充足 | 禁新费用授权，客户担保不侵蚀 | M10 |
| Outbox 提交后崩溃、租约过期旧 worker 复活 | 至少一次恢复，资金语义幂等 | M11 |
| 回调提交后响应丢失、乱序和 DNS 重绑定 | 幂等消费、版本处理、SSRF 阻断 | M11 |
| 恢复旧数据库、根及发行清单 | 发现已签交易，索引不回退，归属正确 | M03/M04/M12 |
| 单人绕过审批、暂停部分失败、审计回退 | 拒绝高风险授权并可追溯 | M13 |

## 9. 容量验证与发布门槛

容量输入至少包括租户/用户数、每秒资金请求、每块 token/native 事件量、地址回填跨度、每日链交易、Webhook 目标数和保留期。以这些输入测量 PG 锁等待、RPC 配额、Signer/KMS 延迟、内存分配与任务积压，确定池大小和分片策略。

发布证据必须覆盖：借贷平衡/非负余额、跨租户隔离、签名硬规则、唯一有效付款、完整充值覆盖、费用资本担保、联合检查点对账、离线密钥恢复和旧 DB 恢复屏障。灰度期间限租户、限资产、限单笔与总暴露，并验证暂停/恢复可用。

尚待产品/部署确定：首条网络与白名单合约、外部 ID 字符集、服务费与最低提现、付款 SLA、风险阈值、在线资本上限、RPO/RTO 故障模型和审计保留期。这些配置有明确模块归属，可在实现前逐项冻结。
